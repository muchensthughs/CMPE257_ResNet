# CMPE257 ResNet — Residual Connection Variants

A controlled study comparing four residual connection variants on CIFAR-10.
All variants share an identical flat-64 block structure; only the skip-connection
mechanism differs. The depth ladder (4 / 32 / 50 layers) is chosen to demonstrate
the *degradation problem* from He et al. 2015: plain networks should exhibit
higher training error as depth grows, while residual variants should not. See
`Exploring_Residual_Connection_Variants_in_Modern_CNN_Architectures.pdf` for
the full experimental design.

## Variants

| Variant       | Formula                | Config files                                              | Status      |
|---------------|------------------------|-----------------------------------------------------------|-------------|
| `baseline`    | `y = F(x) + x`         | `baseline_4.yaml`, `baseline_32.yaml`, `baseline_50.yaml` | Implemented |
| `no_residual` | `y = F(x)` (ablation)  | `plain_4.yaml`, `plain_32.yaml`, `plain_50.yaml`          | Implemented |
| `scaled`      | `y = x + α·F(x)`       | `scaled_4.yaml`, `scaled_32.yaml`, `scaled_50.yaml`       | Implemented |
| `gated`       | `y = x + g(x)·F(x)`    | `gated_4.yaml`, `gated_32.yaml`, `gated_50.yaml`          | Implemented |

Config naming follows `configs/{variant}_{depth}.yaml`. Each variant runs at
three depths (4, 32, and 50 layers), for **12 total runs**.

## Getting Started

### 1. Install

```bash
cd CMPE257_ResNet
python -m venv venv
source venv/bin/activate
pip install torch torchvision pyyaml
```

The CIFAR-10 dataset is downloaded automatically into `data/` on first run.

### 2. Train a single variant

All training is driven by YAML configs in `configs/`. The CLI only takes paths.

```bash
# Baseline at each depth
python scripts/train.py --exp_config configs/baseline_4.yaml
python scripts/train.py --exp_config configs/baseline_32.yaml
python scripts/train.py --exp_config configs/baseline_50.yaml

# Plain (no residual) at each depth — degradation expected at depth 50
python scripts/train.py --exp_config configs/plain_4.yaml
python scripts/train.py --exp_config configs/plain_32.yaml
python scripts/train.py --exp_config configs/plain_50.yaml

# Other variants follow the same naming convention:
# configs/{gated,scaled}_{4,32,50}.yaml
```

Each run takes 200 epochs. Artifacts (checkpoints, logs, per-epoch metrics)
land in `runs/<auto-generated-run-name>/`.

### 3. Train all 12 runs sequentially

```bash
for cfg in configs/baseline_{4,32,50}.yaml \
           configs/plain_{4,32,50}.yaml    \
           configs/gated_{4,32,50}.yaml    \
           configs/scaled_{4,32,50}.yaml; do
  python scripts/train.py --exp_config "$cfg"
done
```

Note: depth-50 plain may diverge or stall — that's the degradation finding,
not a bug. Capture the result rather than retrying with different hyperparameters.

### 4. Resume an interrupted run

```bash
python scripts/train.py \
  --exp_config configs/baseline_50.yaml \
  --resume runs/<run_name>/best.pt
```

### 5. Override the output location

```bash
python scripts/train.py \
  --exp_config configs/baseline_4.yaml \
  --output_dir /tmp/test_runs
```

## What each run produces

In `runs/<run_name>/`:

- `config.json` — the merged config actually used for the run
- `best.pt` — checkpoint with best validation accuracy
- training log with per-epoch train/val loss & accuracy
- per-epoch mean L2 gradient norm across all Conv2d layers
- per-layer gradient norm snapshots at epochs 1, 50, 150

## Training settings (locked per project spec)

- SGD, lr=0.1, momentum=0.9, weight_decay=1e-4
- StepLR: ×0.1 at epoch 100, ×0.1 again at epoch 150
- 200 epochs, no warmup
- Augmentation: RandomCrop(pad=4), RandomHorizontalFlip, CIFAR-10 normalize

These settings are identical across all variants so any observed difference
is attributable to the skip-connection mechanism alone.
